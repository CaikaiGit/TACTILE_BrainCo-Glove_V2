# 强脑手套左右手差异

## 结论

左右手使用相同的 MCU 引脚、FPC 接口逻辑编号、扫描方向和串口协议。物理软板虽然互为镜像，但网络名已经统一成相同的逻辑坐标，因此程序不需要把 X 或 Y 的扫描顺序反转。

当前左右手程序的点位差异只在食指。拇指、中指、无名指和小指使用相同的有效点掩码及区域划分。

| 项目 | 左手 | 右手 | 是否不同 |
| --- | --- | --- | --- |
| MCU 与采集板引脚 | 相同 | 相同 | 否 |
| 扫描顺序 | 手指→Y→有效X | 手指→Y→有效X | 否 |
| 协议数据顺序 | 固定有效点表中按Y、X递增，每点低字节在前 | 固定有效点表中按Y、X递增，每点低字节在前 | 否 |
| 拇指 | 63点，2个区域 | 63点，2个区域 | 否 |
| 食指 | 62点，3个区域 | 62点，3个区域 | **点数相同，Y2位置不同** |
| 中指 | 81点，3个区域 | 81点，3个区域 | 否 |
| 无名指 | 81点，3个区域 | 81点，3个区域 | 否 |
| 小指 | 63点，3个区域 | 63点，3个区域 | 否 |

## 左右食指的实际差异

左右食指都扫描完整的逻辑矩阵 `Y0～Y12 × X0～X7`，区域边界也相同：

- 区域1（指尖）：Y0～Y6
- 区域2（指中）：Y7～Y9
- 区域3（指根）：Y10～Y12

程序的硬件扫描顺序没有区别。PGA 每次选定一根手指，再按 Y 递增、有效 X 递增采集。左右食指的区别由有效点掩码决定；无效交叉点不采集，也不上传。

| Y 行 | 左手食指有效 X | 右手食指有效 X | 差异 |
| --- | --- | --- | --- |
| Y0～Y1 | X3、X4 | X3、X4 | 相同 |
| Y2 | X3 | X4 | 坐标不同 |
| Y3 | X7 | X7 | 相同；两手均去掉 X3 |
| Y4 | X0、X3、X6、X7 | X0、X3、X6、X7 | 相同 |
| Y5～Y6 | X0～X7 | X0～X7 | 相同 |
| Y7～Y12 | X2～X7 | X2～X7 | 相同 |

用集合表示：

- 右手特有点：`(X4,Y2)`
- 左手特有点：`(X3,Y2)`
- `(X3,Y3)` 在左右手中都不采集、不上传。
- 因此左右食指均为62点，左右整手均为350点。

食指采集板接口 J2 的针脚网络在左右手原理图中一致：1～13脚依次为 Y0～Y12，14～21脚依次为 X7～X0。左右食指 PCB 的连接器针脚网络也一致，说明物理镜像没有要求程序反向扫描。

## 拇指 Y 编号说明

采集板拇指接口使用 Y0～Y12，而拇指软板对应传感行标成 Y1～Y13，两边网络名称整体相差1。程序以采集板/MCU编号为准：

- 第一包：采集板 Y0～Y6，对应软板 Y1～Y7，尺寸 `8×7`
- 第二包：采集板 Y7～Y12，对应软板 Y8～Y13，尺寸 `8×6`

这不是左右手差异，左右拇指都使用同一映射。

## 程序选择

- 右手工程：`plam-hc32-base`，`STRONG_GLOVE_HAND_RIGHT=1`
- 左手工程：`plam-hc32-base - ZS`，`STRONG_GLOVE_HAND_RIGHT=0`

条件编译只切换食指有效点掩码；扫描函数、引脚表、其他四指点位和协议打包代码通用。
